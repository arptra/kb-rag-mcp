# Текущие страницы и возобновление индексации

Индексы обслуживают только текущее содержимое страниц. Confluence загружает свежую
версию и заменяет материализованный документ при изменении. Обход прошлых редакций,
их индексация и выбор состояния на дату отключены. Сохранённый параметр
`include_history=true` автоматически трактуется как `false`.

В интерфейсе документа доступны актуальный текст, изображения и информация об
обновлении. Вкладки истории и выбора даты больше нет. Журнал синхронизаций и очередь
повторных попыток продолжают работать.

## Контракты MCP, A2A и HTTP

Имена существующих инструментов сохранены. `kb_search`, `kb_search_index` и
совместимый `kb_search_versions` ищут только в текущем индексе. Старые аргументы
`version_scope`, `as_of` и `source_version` больше не выбирают прошлую версию.
Ответ поиска явно сообщает `version_scope: "latest"` и `as_of: null`.

`kb_get_document` принимает актуальный `document_id` или стабильный `page_id`.
Для чтения после очередного обновления используйте `page_id` либо свежий ID из
результата поиска. Снятый с публикации `document_id` или `chunk_id` возвращает
ошибку отсутствия документа; архив не используется как запасной источник.

```json
{"query":"правила платежей", "index_id":"team-docs"}
```

```json
{"index_id":"team-docs", "page_id":"confluence:team:123"}
```

A2A работает так же: `search`, `document` и `chunk` читают текущий индекс.
Совместимое действие `versions` и HTTP-ручка `/admin/api/indexes/document/versions`
возвращают максимум одну текущую страницу. Старые определения managed tools с
историческими настройками нормализуются в режим `latest`.

Номер версии источника и даты остаются справочной информацией:

| Поле | Значение |
| --- | --- |
| `page_id` | Стабильная логическая страница |
| `document_id` / `chunk_id` | Идентификатор текущего документа или фрагмента |
| `source_version` | Номер текущей версии в источнике, если известен |
| `source_updated_at` | Дата изменения страницы в источнике |
| `revision_updated_at` | Дата обновления с учётом вложений |
| `fetched_at` | Время получения содержимого |
| `is_latest` | `true` для возвращаемых документов и фрагментов |

Фильтры `updated_from` и `updated_to`, если переданы, ограничивают даты изменения
текущих страниц, а не выбирают исторические редакции. Бизнес-статус `status`
(`current`, `deprecated` и т. п.) сохраняет прежний смысл. Потеря доступа к странице
по-прежнему закрывает её поиск и чтение.

## Переход со старой версии

При обновлении существующие файлы архивов не удаляются. Они не участвуют в поиске,
чтении страниц или обработке новых индексов; новые исторические снимки не создаются.
Подготовленный кеш открывается без переноса документов и чанков в архив перед
запуском HTTP-сервера. Отложенная индексация старой истории также не выполняется.
Если старый кеш содержит несколько редакций одной логической страницы, при загрузке
для выдачи выбирается только самая свежая.

Для применения обновления перезапустите бэкенд и обновите собранный интерфейс.
Пересоздавать подключения и индексы не нужно. При следующей синхронизации
Confluence проверит текущие страницы и обновит изменившиеся.

## Контрольные точки и публикация

Название `KB_HISTORY_DIR` и путь `var/history` оставлены для совместимости установки.
Теперь сервис использует эту базу для ограничения видимости страниц и сохранения
готовых embedding-векторов. Исторический текст документов и чанков туда больше не
записывается. Сохраняйте каталог при обновлении и очистке disposable-кеша.

Embeddings рассчитываются пакетами `KB_EMBEDDING_CHECKPOINT_BATCH_SIZE` (по умолчанию
32). Готовый пакет сохраняется транзакционно; ключ включает текст для embedding и
идентичность провайдера/модели. После сбоя переиндексация с переиспользованием кеша
продолжает с отсутствующих результатов. Незавершённый пакет рассчитывается снова.
Если после обновления есть подготовленный индекс, но ещё нет базы контрольных точек,
при пересборке готовые векторы переиспользуются из индекса без архивирования страниц.

Сборочная матрица размещена в mmap-файле. Новый кеш публикуется атомарно в
`generations/<id>/` переключением `CURRENT` после проверки результата. Ошибка
сборки или публикации сохраняет предыдущий рабочий индекс. При наличии нескольких
файлов одной логической страницы выбор текущего документа выполняется до chunking
и embedding, чтобы не обрабатывать устаревшие экспорты.

Большие сборки ограничиваются временем без прогресса
`KB_INDEX_BUILD_NO_PROGRESS_TIMEOUT_SECONDS`, а не общим временем работы.
`KB_INDEX_BUILD_OVERALL_TIMEOUT_SECONDS` задаёт дополнительный общий предел, если
он необходим. Статус и прогресс доступны в журнале операций.
