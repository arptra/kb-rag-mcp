03 / 08

Честно про реализацию

Вектор есть.
Но пока он лексический.

Текст «дневной лимит»
→
Слова + триграммы лимит · ^ли · лим · ими…
→
Нормализованный вектор [0, −1, 2, 0, …] хэширование признаков → косинусная близость
Не путать
с SHA документа

SHA-256 документа нужен для ID и кэша. Хэш-провайдер отдельно строит поисковый вектор из текста.

Семантические эмбеддинги уже поддержаны: локальную Qwen-модель можно включить без изменения MCP-контракта.

→

Не нужно угадывать название страницы. Нужен только вопрос по задаче.

06 / 08

Кросс-сервисная фича

Граф определяет маршрут.
RAG наполняет его фактами.

Описание
фичи цель и сценарий
→
Граф
сервисов HTTP · Kafka · уровень уверенности
→
RAG каждого
сервиса локальные контракты и правила
→
План по
репозиториям миграции · тесты · rollout
→
Эпик → История
→ Задача в Jira-проектах команд

Низкая уверенность и неразрешённые связи остаются гипотезами — план должен вынести их в отдельную проверку, а не выдавать за факт.

07 / 08

Итог

Confluence хранит знания.
RAG доставляет контекст.

Ручной поиск

знать папку → угадать название → открыть страницы → проверить актуальность → собрать связи

VS

RAG + граф

описать задачу → получить сервисы → увидеть источники → перейти к плану

Хэш-поиск хуже понимает синонимы и смысл.
Индекс должен регулярно обновляться.
Статический граф — не трассировка выполнения.
Следующий шаг Семантические эмбеддинги + измерение качества

Затем — гибридный поиск, реранкер и векторная БД по мере роста.
