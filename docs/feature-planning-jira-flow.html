Почему это масштабируется

Агент не отправляет вопрос во все индексы. Сначала граф выбирает root и соседей, затем выдаёт точные next_calls только для затронутых knowledge boundaries.

Граница достоверности

Static graph показывает возможные связи в исходниках, а не production trace. LOW и UNRESOLVED остаются гипотезами.

Результат planning-контура

Не код и не Jira issues, а согласуемый набор изменений: affected services, contracts, migrations, dependencies, rollout, тесты, risks и citations.

Read-only boundary

Skills могут вызывать только retrieval/routing tools. Clone, graph rebuild, SSOT submit и Jira writes не запускаются ради обычного плана.

Target write extension

Декомпозиция и Jira delivery

Новая надстройка получает согласованный план, маршрутизирует work packages по командам и только после preview и явного подтверждения создаёт задачи.

06
Delivery result

Вернуть Jira keys и traceability

Финальный ответ содержит созданные issue keys, проекты, ссылки, ошибки частичного создания и цепочку доказательств для каждого scope item.

Минимальный Jira payload

Project key, issue type, summary, description, acceptance criteria, component, labels, owner/team, parent, links, evidence IDs и graph revision.

Защита от дублей

Идемпотентность должна строиться по feature ID + plan revision + service ID. Повторный запуск обновляет preview, а не создаёт второй набор задач.
