# Включение агента GigaCode и авторизация

Агент включается администратором через кнопку «Включить агента». Сервер запускает
короткую проверку GigaCode без документов. Если CLI печатает ссылку входа, интерфейс
показывает её администратору и состояние «Требуется авторизация». После входа проверка
заканчивается и агент становится готов к исследованию документов. Повторное нажатие
во время запуска не создаёт дополнительный процесс.

Если авторизация понадобится во время исследования, новая ссылка также появляется
в администрировании. Ссылка не включается в ответ внешнему агенту, общий журнал или
историю событий. В журнале остаются переходы состояния. CLI учитывает существующий
`KB_GIGACODE_AUTH_TIMEOUT_SECONDS`. Workflow отдельно приостанавливает рабочий таймер
исследования на время входа и ограничивает суммарное ожидание настройкой
`HARNESS_AUTHENTICATION_TIMEOUT_SECONDS` (по умолчанию 600 секунд). Повторные запросы
авторизации внутри одного исследования не сбрасывают этот лимит. Если лимит исчерпан,
запуск останавливается и просит завершить вход через администратора, затем повторить
исследование. Отмена действует и во время ожидания входа.

Кнопка выключения отменяет активный вызов и ожидающие запуска вызовы этого
контроллера. Старые сообщения от завершённого процесса не могут снова включить
агента или вернуть старую ссылку. После перезапуска backend агент выключен;
администратор включает его снова. Сохранённая самим CLI авторизация не удаляется.

## Настройка на сервере

Используется существующий `KB_GIGACODE_COMMAND` и файл профиля, указанный в
`KB_HARNESS_MODEL_PROFILE_PATH`. Дополнительные зависимости LangChain для этого
контроллера не нужны. Файл содержит:

```json
{
  "name": "corporate-model-only",
  "cli_version": "EXACT_OUTPUT_OF_VERIFIED_LAUNCHER_VERSION",
  "arguments": [],
  "isolation_notes": "Describe how this launcher disables native tools, inherited MCP, hooks and ambient context."
}
```

Это описание формата, а не готовый профиль для копирования. `cli_version` должна
точно совпадать с результатом `--version` проверенного запускающего файла.
`arguments` содержит только действительно поддерживаемые им параметры политики.
Пустой список допустим для обёртки, которая уже обеспечивает нужные ограничения.
Файл профиля — доверенная серверная настройка: внешний агент не может выбрать
команду, параметры или профиль через запрос.

Для каждого модельного шага runner создаёт пустую временную рабочую директорию,
не продолжает предыдущую CLI-сессию, принимает структурированный JSON и запрещает
нативные события вызова инструментов. Сам агент выбирает `search_knowledge` или
`read_document` в JSON, а сервер проверяет аргументы и права перед их выполнением.
Одновременно работает не более одного CLI-вызова этого контроллера. Переданный
в profile текст сам по себе не отключает инструменты и не создаёт sandbox.

## Что подтверждено документацией и что нужно проверить на установленном CLI

Официальная документация описывает
[команды управления авторизацией и инструментами](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/commands),
[наследование и фильтрацию MCP](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/mcp)
и [allowlist инструментов субагентов](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/subagents).
Из этих страниц нельзя подтвердить универсальный набор параметров запуска главного
CLI, который для конкретной корпоративной версии одновременно отключает все
нативные инструменты, наследованные MCP, hooks и пользовательский контекст,
сохраняя browser OAuth. Настройки субагента не доказывают ограничения основного CLI.
Поэтому код не подставляет выдуманные `--no-tools`/`--disable-mcp` и не запускает
обычный unrestricted CLI при отсутствии профиля.

Администратору развёртывания нужно проверить такую конфигурацию на установленной
версии либо предоставить проверенную обёртку. При отсутствии профиля, несовпадении
версии или недоступности команды кнопка показывает конкретную причину. После
исправления настройки повторное включение выполняет новую проверку.

В локальной среде настоящий корпоративный CLI отсутствует. Тестами с имитатором
проверены получение ссылки, завершение и повторная авторизация, отмена,
последовательное исполнение, защита от старых callback, проверка JSON и отсутствие
секретов в событиях/ошибках. Это не заменяет проверку корпоративного входа и
политики запуска на сервере.
