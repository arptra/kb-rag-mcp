# Включение агента GigaCode и авторизация

Агент включается администратором через кнопку «Включить агента». Сервер запускает
короткую проверку GigaCode без документов. Если CLI печатает ссылку входа, интерфейс
показывает её администратору и состояние «Требуется авторизация». После входа проверка
заканчивается и агент становится готов к исследованию документов. Повторное нажатие
во время запуска не создаёт дополнительный процесс.

Если авторизация понадобится во время исследования, новая ссылка также появляется
в администрировании. Ссылка не включается в ответ внешнему агенту, общий журнал или
историю событий. В журнале остаются переходы состояния. CLI учитывает существующий
`KB_GIGACODE_AUTH_TIMEOUT_SECONDS`. Workflow отдельно приостанавливает рабочий таймер
исследования на время входа и ограничивает суммарное ожидание настройкой
`HARNESS_AUTHENTICATION_TIMEOUT_SECONDS` (по умолчанию 600 секунд). Повторные запросы
авторизации внутри одного исследования не сбрасывают этот лимит. Если лимит исчерпан,
запуск останавливается и просит завершить вход через администратора, затем повторить
исследование. Отмена действует и во время ожидания входа.

Кнопка выключения отменяет активный вызов и ожидающие запуска вызовы этого
контроллера. Старые сообщения от завершённого процесса не могут снова включить
агента или вернуть старую ссылку. После перезапуска backend агент выключен;
администратор включает его снова. Сохранённая самим CLI авторизация не удаляется.

## Настройка на сервере

Штатный агент A2A использует тот же `GigaCodeRunner.run_json`, что уже используется
для анализа в приложении. Нужны существующие настройки `KB_GIGACODE_ENABLED=true`
и `KB_GIGACODE_COMMAND` с рабочей командой GigaCode. Отдельные API-токены, адрес
модели, выбор модели и файл профиля запуска для агента не требуются. Дополнительные
зависимости LangChain для этого контроллера также не нужны.

GigaCode использует свою конфигурацию и сохранённую авторизацию пользователя ОС,
от которого запущен backend. Если CLI уже работает при анализе из этого backend,
агент использует тот же способ запуска. Вход под другим пользователем ОС не
авторизует процесс backend; в таком случае завершите вход по ссылке из панели A2A.

После обновления файлов перезапустите backend, чтобы он загрузил новый контроллер.
Затем откройте вкладку **A2A**, нажмите **«Включить агента»** и при необходимости
**«Пройти авторизацию GigaCode»**. После успешной проверки появится статус готовности.
При недоступной команде или ошибке входа панель показывает причину; после исправления
нажмите **«Повторить запуск агента»**.

`KB_HARNESS_MODEL_PROFILE_PATH` не используется этим контроллером, даже если
переменная уже задана и указывает на отсутствующий или некорректный файл.
Она остаётся настройкой модельного адаптера отдельной экспериментальной страницы
[`/harness/`](README.harness.md). Включать эту страницу ради агента A2A не требуется.

Для проверки и каждого модельного шага используется пустая временная рабочая
директория. Агент не продолжает предыдущую CLI-сессию и получает решение в
структурированном JSON. Он выбирает `search_knowledge` или `read_document`, а сервер
проверяет аргументы и права перед выполнением. Одновременно работает не более
одного CLI-вызова этого контроллера.

## Границы запуска и проверки

Применяются существующие исключения инструментов для анализа. Если CLI присылает
нативное событие вызова инструмента вместо JSON-решения, такой запуск отклоняется.
Это контроль протокола выполнения, а не изоляция процесса средствами ОС:
пользовательская конфигурация CLI сохраняется, отключение всех её MCP-настроек,
hooks и прочего контекста не гарантируется. Внешний агент не может передать свою
команду запуска, CLI-параметры или расширить разрешённые ему индексы.

В локальной среде настоящий корпоративный CLI отсутствует. Тестами с имитатором
проверены получение ссылки, завершение и повторная авторизация, отмена,
последовательное исполнение, защита от старых callback, проверка JSON и отсутствие
секретов в событиях/ошибках. Это не заменяет проверку корпоративного входа и
политики запуска на сервере.
