# Agent Harness

Самостоятельный модуль вопросов и исследований: собственная страница, HTTP API,
очереди быстрых запросов и исследований, «Автопилот», усилие, отмена, LangGraph и личная история SQLite.
Пакет не импортирует портал, его RAG, GigaCode или интерфейс dashboard.

В полном репозитории подготовьте зависимости и образы одной командой из его корня:

```sh
./scripts/setup-harness.sh
```

Нужен uv или Python 3.12; для образов также нужен работающий Docker Engine.
По умолчанию скрипт использует установленный uv и версии из `uv.lock`; если uv нет,
устанавливает зависимости через обычный pip по ограничениям `pyproject.toml`.
Сам uv не скачивается. Скрипт сохраняет существующие дополнительные пакеты и заранее
собирает `harness-sandbox:local` и `harness-sandbox-java21:local`.
Повторная сборка использует кэш. `--deps-only` обновляет только библиотеки Python.
После обновления кода и зависимостей перезапустите backend. Во время вопросов
установка инструментов не запускается.

В корпоративной сети выбирайте `./scripts/setup-harness.sh --installer pip`:
этот режим использует настройки pip, прокси и каталога пакетов без принудительного
публичного PyPI. Он работает без uv, даже если uv уже установлен в системе; версии
разрешаются из `pyproject.toml`, а `uv.lock` не используется. Для обновления только
библиотек добавьте `--deps-only`. Режим `--installer uv` требует установленный uv
и сохраняет точные версии из lock-файла, без автоматического перехода на pip при ошибке.

В этой версии обязательны `langchain`, `langchain-text-splitters`, `langgraph` и
`langgraph-checkpoint-sqlite`. После обновления кода выполните
`./scripts/setup-harness.sh --installer pip --deps-only`, затем перезапустите backend.

В экспортированном самостоятельном пакете установите проект из каталога с
`pyproject.toml`: `pip install .`; скрипты родительского репозитория туда не входят.
Задайте секрет `HARNESS_API_TOKEN` длиной не менее 32 символов и запустите
`python -m agent_harness`. По умолчанию страница доступна на
`http://127.0.0.1:8020/`. В форме входа выберите токен. Секрет не передаётся в URL.
Адрес и порт задаются `HARNESS_HOST` и `HARNESS_PORT`.

Общий `HARNESS_API_TOKEN` разрешает пользоваться чатом, но не администрировать сервис.
Для управления задайте отдельный `HARNESS_ADMIN_TOKEN` не короче 32 символов
и войдите с ним. Он должен отличаться от пользовательского токена; без него
административный доступ закрыт. В портале нужны права администратора или
явно заданный пароль администратора, общий токен чтения для управления не подходит.

При обновлении существующего standalone из полного репозитория выполните
`git pull --ff-only`, затем `./scripts/setup-harness.sh --installer pip --deps-only`.
Остановите прежний процесс через `Ctrl+C` и повторите
`PYTHONPATH=src .venv/bin/python -m agent_harness` с прежними `HARNESS_API_TOKEN`,
`HARNESS_STATE_DIR`, `HARNESS_PROVIDER_FACTORY` и отдельным `HARNESS_ADMIN_TOKEN`.
Токены задаются в окружении процесса: одной записи в `.env` для них недостаточно.
Скрипт установки не перезапускает сервер. Сохраняйте прежний каталог SQLite:
чаты, память и подключения не требуют сброса. После перезапуска обновите страницу;
администратору доступен `/control/`, пользователю с обычным токеном — только чат.
В экспортированном проекте вместо отсутствующего `setup-harness.sh` обновите
зависимости командой `python -m pip install --upgrade .` в его виртуальном окружении.

Без провайдеров интерфейс сообщает, что источники и модель не подключены.
Для реальной работы задайте `HARNESS_PROVIDER_FACTORY=my_package.providers:create`.
Функция без аргументов возвращает `(source, model)` по интерфейсам `contracts.py`.
Провайдеры — доверенный серверный код. Они проверяют права на каждом чтении,
ограничивают результаты и реагируют на `cancel`. Модель должна возвращать проверенный
JSON `content` / `tool_calls`; собственных внешних действий она не выполняет.

Токен стандартного standalone-входа представляет одну общую учётную запись. Для
личной истории нескольких пользователей передайте в `http.create_app` собственную
функцию `authenticate(request) -> Principal | None` со стабильным серверным owner_id.
Не доверяйте `owner_id`, присланному браузером. Источники должны повторно проверять
права при выполнении фоновой работы.

Провайдер модели может дополнительно экспортировать `model_control` с методами
`status`, `enable`, `disable` и метод `close()` самого провайдера для очистки при
остановке. Standalone даёт управление моделью только обладателю `HARNESS_ADMIN_TOKEN`.
При встраивании `http.create_app` принимает отдельный `authorize_model_manager`;
без него административные сведения и действия недоступны обычным читателям.

Хранилище задаётся `HARNESS_STATE_DIR`; используйте постоянный локальный каталог на процесс.
Отдельный сервер БД не нужен: история и память живут в `runs.sqlite3`, шаги LangGraph —
в `checkpoints.sqlite3`, подключения — в `configuration.sqlite3`, бюджеты —
в `control.sqlite3`, обнаружения —
в `discoveries.sqlite3`. Память общая для всей АС; история и обнаружения разделены по
серверному владельцу. Отдельная БД для каждого человека не создаётся.
Один процесс обслуживает две независимые очереди; несколько ASGI workers или реплик
над этим хранилищем не поддерживаются. Для такого масштабирования нужны внешняя
очередь и серверная БД. Незавершённые работы после
перезапуска помечаются прерванными. LangGraph сохраняет шаги через AsyncSqliteSaver;
явное продолжение проверяет доступы, сохраняет бюджеты и не повторяет неопределённый
внешний вызов. Общая память АС автоматически собирает кейсы запусков и уроки ошибок
всех пользователей, учитывает оценки ответов и использует подходящий прошлый опыт
при похожих запросах коллег с доступом ко всем исходным индексам записи.
Автокейсы явно помечены как неподтверждённые и не заменяют свежие источники.
Повторное применение опыта сохраняет результат следующего запуска и его оценку.
Общие счётчики полезных/неудачных применений помогают ранжировать равно релевантные
записи; неудачное применение становится предостережением для нового исследования.
Комментарии и источники последующего пользователя не копируются в чужую запись,
обновляется только агрегированная статистика.
В разделе памяти виден общий счётчик использования. Черновики личные, подтверждённые
заметки общие; изменить или удалить запись может автор. Личный переключатель отключает
автоматическое использование и пополнение памяти только для своих запросов.
Переобучения весов нет. Старые записи становятся общими без сброса SQLite.
Чаты можно удалить вместе с продолжениями и контрольными точками. Общая память при
удалении или очистке старой истории сохраняется без ссылки на чат; связанные личные
черновики удаляются. По умолчанию память ограничена 10 000 записями на АС, без отдельных
пользовательских квот; её объём настраивается администратором.

Статические файлы лежат в `static/` и не требуют Node, сборки или CDN.
Интерфейс показывает разговор целиком с подгрузкой истории, реальные текущие действия,
план и оставшиеся проверки. История подбирается по бюджету токенов, без фиксированного
ограничения в 12 пар сообщений. Чаты сохраняются под устойчивым `conversation_id`; доступны
`GET /api/conversations`, `GET /api/conversations/{id}` и удаление всей беседы.
LangGraph выполняет цикл `decide → tools → reflect → decide` после подготовки источников;
план и результаты каждого раунда входят в контрольные точки. Пустой или обрезанный
итог получает ограниченную повторную попытку, а незавершённость явно показывается.
Сервис можно монтировать в другой Starlette/ASGI app под собственным префиксом.
Родительское приложение должно запускать lifespan модуля и останавливать его вместе
со своими задачами. Не подключайте модуль, когда его feature flag выключен.

**Автопилот** (`mode="autonomous"`) использует тот же LangGraph-цикл исследования
и очередь исследований. Его отличие — инструмент `request_budget`: модель объясняет
следующую проверку и запрашивает нужный объём времени, вызовов или контекста.
Сервер ограничивает запрос потолками администратора, числом расширений и проверкой
новых подтверждений. Запросы и решения сохраняются в истории работы. Режимы
`quick` и `investigate` не расширяют свои бюджеты автоматически. Изменение бюджета
не даёт новых прав, подключений или полномочий на выполнение команд.

Административная страница `/control/` полностью отдельна от чата; её файлы находятся
в `control/static/`, графики используют локальный Chart.js без CDN. При монтировании
в портале адрес — `/harness/control/`. `HARNESS_CONTROL_ENABLED=false` с перезапуском
отключает страницу и её API, сохраняя работу Harness и действующие ограничения.
Тот же `authorize_model_manager` защищает настройки, метрики и остановку запуска.

На странице задаются профили режимов и усилия, потолки Автопилота, параметры
контекста, памяти, очередей, таймаутов, повторных попыток и хранения. Профили и потолки
закрепляются при постановке нового запроса в очередь; сохранение новой редакции
не переписывает бюджет уже выполняющейся работы. Размер очередей и число обработчиков
применяются после перезапуска. Настройки сохраняются атомарно с проверкой редакции.
`source_timeout_seconds` ограничивает RAG, `external_tool_timeout_seconds` — внешние
инструменты; оба дополнительно ограничены оставшимся временем исследования.
`max_decision_errors` задаёт число ошибок решения модели перед итоговым ответом.
При явном продолжении прерванной работы запас вызовов и редакция политики сохраняются,
а окно времени начинается заново. Чтобы применить новую политику, создайте новый запрос.

Основные вызовы модели и вызовы сжатия имеют отдельные бюджеты. Основной бюджет
включает итоговый ответ и запросы увеличения ресурсов; дополнительные попытки
исправить некорректный итог задаются через `max_answer_retries`. В статистике
`model_calls` учитывает все вызовы, `decision_calls` — основные,
`summary_calls` — сжатие. Оценка токенов и usage от API модели показаны отдельно;
отсутствие usage обозначается `null`. Графики отражают только сохранившиеся запуски.
Администратор видит технические показатели и может остановить работу, не получая
текст личного чата, его владельца или содержимое источников.

API относительно точки монтирования:
`GET/PUT /api/control/settings`, `GET /api/control/metrics?days=7`,
`POST /api/control/runs/{run_id}/cancel` с `{}`. Последний возвращает только
`{id,status}`; мутации требуют административных прав и проверки CSRF.

**Сжатие беседы** выполняет библиотечный `SummarizationMiddleware` LangChain.
Он проверяет оценку токенов, сохраняет последние сообщения и создаёт сводку
старой части через подключённый `ModelPort`. Длинный текст обрабатывается
библиотечным разбиением. LangGraph остаётся движком исследования; DeepAgents
не подключён. Исходная переписка не переписывается и не удаляется при сжатии.

Сводки в SQLite кэшируются отдельно по владельцу и ветке разговора. Перед их
использованием проверяются исходные сообщения, выбранная область и текущий доступ;
удалённые или просроченные сообщения удаляются и из кэша. Эти сводки не являются
общей памятью АС. Поля `context_summary` показывают размер до/после, число сжатий
и повторное использование кэша. Ошибка или недостаток бюджета явно останавливает
подготовку контекста; Автопилот может запросить его расширение в разрешённых пределах.

Окно модели задаёт оператор (`context.window_tokens`, по умолчанию 65 536), резерв
ответа — 4 096. Это не автоматическое определение возможностей GigaCode. Входной
бюджет не превышает заданное окно за вычетом резерва; подсчёт токенов приблизительный,
с настраиваемым коэффициентом. Реальные ограничения провайдера, rate limits и окно
модели нельзя увеличить настройками Harness.

Встроенный `IntegrationHub` реализует `ToolPort`: репозитории в Docker, MCP Streamable
HTTP и A2A JSON-RPC 0.3. Администратор управляет ими через «Настройки». Конфигурация
общая, в `HARNESS_STATE_DIR/configuration.sqlite3`; старый `integrations.json`
импортируется один раз. Индивидуальная область задаётся
`allowed_owners`, пустой список означает всех вошедших. Секреты передаются по имени
переменной окружения сервера и в конфигурацию не записываются. Для подключения с
токеном нужен HTTPS. Доступ к операциям MCP задаётся списком `allowed_tools` и
настройкой `include_read_only_tools`. Быстрый ответ использует RAG, граф сервисов
и разрешённые операции MCP с `readOnlyHint: true` и без `destructiveHint: true`.
Исследование и Автопилот также могут читать код и обращаться к агентам A2A.

Для репозиториев заранее соберите `sandbox.Dockerfile` в `harness-sandbox:local`
и включите песочницы в настройках. `sandbox.java21.Dockerfile` на базе этого образа
добавляет Java 21, `javac` и Maven; тег — `harness-sandbox-java21:local`.
В **Настройки → Песочницы → Дополнительные среды** проверьте включённый профиль
**Java 21** с этим образом. Для Java-запроса выберите **«Исследовать» →
«Среда выполнения» → «Java 21»**; базовый образ остаётся `harness-sandbox:local`.
Зависимости и плагины конкретного Maven-проекта предварительно добавляются в свой образ;
наличие Maven не означает готовность произвольного проекта к сборке без сети. Требуется Linux Docker Engine. Контейнерный код
не получает каталоги хоста; сеть отключена после стадии HTTPS/SSH Git clone,
ресурсы и размер tmpfs ограничены. Песочница удаляется после запроса. Нужные для
тестов/сборок зависимости добавляются в доверенный образ заранее. Автоматическое
скачивание образа и выполнение команд на хосте в обход Docker не предусмотрены.
После падения процесса администратор очищает оставшиеся ресурсы Harness.

SSH-ключи и доверенные `known_hosts` добавляются администратором в настройках.
Ключ используется только контейнером клонирования, не попадает в рабочий том,
интерфейс ответа или модель. Обнаруженные в источниках ссылки видны в интерфейсе;
запрос доступа создаёт обращение администратору и сам не запускает подключение.

По умолчанию модель — переданный фабрикой GigaCode. Во вкладке «Модель» можно выбрать
HTTPS API, совместимый с OpenAI Chat Completions, имя модели, Bearer-переменную сервера
и TLS-набор: корпоративный CA и/или клиентский сертификат с ключом. Проверка TLS
всегда включена; приватные ключи хранятся отдельно от настроек с правами `0600`.

Профиль **DeepSeek Flash V4 · 256K** доступен и для корпоративного URL без имени модели.
Он задаёт окно 256 000, ответ 32 768, входной бюджет 215 040 токенов (с запасом 8 192),
ожидание одного API-вызова 1 800 с и резерв итога с повтором 3 600 с. Исследование
получает 12/24/48 основных вызовов и потолок 4/6/8 ч по усилию; заканчивается сразу
после получения результата. Быстрый режим имеет потолок 65 мин на медленную модель
и восстановление. Автопилот не тратит резерв итога на дополнительный пересмотр бюджета.
Стандартные ограничения старой установки обновляются при выборе профиля; отличающиеся
от стандартов параметры оператора сохраняются. Изменения действуют на новые запросы.

Встроенный thinking DeepSeek отключён: исследование выполняется через LangGraph и
инструменты Harness. Незавершённые tool calls не исполняются, обрыв генерации учитывается
при повторной попытке. Подключённый MCP доступен агенту через `mcp_list_tools` (текущий
разрешённый каталог с поиском), `mcp_tool_schema`, затем `mcp_call`. Метаданные инструментов
не подтверждают факты об АС. Текущая операция и начало ожидания записываются в SQLite
до долгих вызовов и показываются в чате вместе с журналом завершённых действий.
