# Dev Console

Отдельный локальный интерфейс для записи тестовых сеансов и управляемого исправления ошибок.
Собственный Python-модуль `src/dev_console`, HTTP-сервер и статический UI. Основной dashboard и
MCP для его работы не нужны. Механизм записи и исправлений переиспользуется из `corporate_kb.dev_debug`.
Новые npm-зависимости, сборка frontend и отдельная модель не требуются.

## Запуск

В обычном интерактивном терминале на машине с checkout и установленным GigaCode:

```bash
./scripts/dev-console.sh
# То же самое:
./scripts/dev.sh debug-ui
```

Открой ссылку, которую выведет терминал. По умолчанию используется `http://127.0.0.1:8788`,
а ссылка содержит временный ключ доступа. После открытия ключ удаляется из адресной строки и
хранится в sessionStorage этой вкладки. После перезапуска сервера открывай новую ссылку.
Терминал оставь открытым: GigaCode будет запускаться непосредственно в нём.

```bash
./scripts/dev-console.sh --port 8789 --gigacode /path/to/gigacode
```

Скрипт использует существующую `.venv`. Подготовка окружения, если нужна, выполняется отдельно
через `./scripts/dev.sh install` или `./scripts/dev.sh install-pip`. Пакет также предоставляет
`python -m dev_console` и entry point `kb-dev-console` после установки проекта.

## Работа через интерфейс

1. Создай сессию, укажи, что проверяешь. Начнётся наблюдение за логами.
2. Повтори ошибку в основном приложении. Добавь наблюдение: что сделал, что увидел и что ожидал.
3. Нажми «Починить». Сеанс попадёт в цикл анализа и исправления.
4. Во время работы GigaCode интерфейс подскажет перейти в терминал. Там ты подтверждаешь запись
   плана, а позже каждую правку файлов. После завершения каждой фазы введи `/quit`.
5. Предложенный план появится в UI. Утверди или отклони его. Перед проверками UI покажет точные
   команды и попросит разрешить их запуск.
6. Следи за логами и результатами проверок. Когда они пройдут, повтори исходный сценарий на
   обновлённом dev-сервере и подтверди результат в UI. При сбое цикл создаст новую попытку.

UI показывает текущую фазу, историю сессий, состояние записи, план, команды проверок,
последние результаты и диагностические артефакты. Его можно перезагрузить или открыть повторно:
ожидающее подтверждение останется на сервере. Закрытие вкладки ничего автоматически не утверждает.

Кнопка остановки записи прекращает только сбор логов. Отмена исправления прекращает ожидание
решения и следующие шаги; запущенные проверки завершаются. Во время нативной сессии GigaCode
отмена вступит в силу после её завершения: используй `/quit` или штатное прерывание в терминале.
Браузер не отправляет скрытые ответы в CLI и не меняет её режим подтверждений.

## Откуда берутся логи

UI наблюдает стандартные журналы проекта и дополнительные пути, указанные при создании сессии.
Создание сессии разрешает запись диагностических файлов в `.cache/dev-debug`.
Подробности источников, маскирования секретов и лимитов — в [описании dev-режима](README.dev-debug.md).

Чтобы получить исходную причину Git/Skills-ошибки, запусти dev-backend с захватом stdout/stderr
в ещё одном терминале, указав ID сессии из UI:

```bash
./scripts/dev-debug.sh run --session <ID> -- ./scripts/start-backend.sh
```

Если backend уже занимает порт, сначала останови прежний экземпляр обычным способом.
UI сам не запускает и не перезапускает рабочий сервер. Уже отброшенные старым процессом stderr
восстановить нельзя — повтори ошибку с включённым захватом. Консоль браузера приложения не
перехватывается; важные наблюдения добавляй заметкой.

## Разделение модулей

| Модуль | Назначение |
| --- | --- |
| `dev_console.server` | Локальный HTTP API, доступ к UI и проверка ключа/Origin |
| `dev_console.controller` | Запись, очередь одной задачи, состояние и подтверждения из браузера |
| `dev_console.__main__` | HTTP в отдельном потоке, GigaCode в основном потоке с реальным TTY |
| `dev_console/static` | Самостоятельный HTML/CSS/JS интерфейс без внешних ресурсов |
| `corporate_kb.dev_debug` | Сбор логов, пакеты, проверяемый цикл исправлений и запуск CLI |

HTTP-обработчик только ставит исправление в очередь. GigaCode запускает владелец исходного
терминала, с обычными правами и подтверждениями. Планы не могут менять сами модули dev-debug,
Dev Console и их скрипты. Одновременно из UI может выполняться одно исправление проекта.
Завершение процесса UI не возобновляет старые разрешения после следующего запуска.

Сервер слушает только `127.0.0.1`, проверяет Host/Origin и ключ на всех API-запросах.
Ключ не сохраняется в диагностических пакетах, нет CORS и произвольного shell endpoint.
Это локальный dev-инструмент; для удалённой машины используй локальный SSH port forwarding и
интерактивный SSH-терминал. Публикация через общий reverse proxy здесь не предусмотрена.

Без интерактивного терминала доступны просмотр и запись, а запуск исправлений запрещён.
Проверка GigaCode показывает наличие бинарника и совместимость флагов, но не заменяет его
авторизацию и проверку доступа к модели. Режим не обещает исправлять любую проблему:
ошибки окружения, отсутствие доступа и лимиты попыток остаются видимыми причинами остановки.
