# Агенты портала

Страница **Агенты** доступна по адресу `/agents/`. Это чат с агентом Deep Agents SDK.
Модель сама выбирает следующий шаг. На обычный вопрос она может ответить сразу.
Для отдельного приветствия вроде «Привет, как дела?» SDK обращается к модели
с пустым списком инструментов. У приветствия, за которым следует задача,
доступ к инструментам сохраняется.
Для вопроса о релизе она может запросить список индексов, выбрать один по описанию,
выполнить поиск, открыть найденный документ и сопоставить дату с записью из MCP.
Выбор зависит от вопроса, доступных инструментов и фактических результатов.
В чате отображаются обращения к модели и вызовы инструментов.
Через корпоративный адаптер gpt2giga агент начинает выбор источника с короткого
текстового обращения к настроенной модели. Она получает вопрос и каталог доступных
операций чтения. Например, для списка индексов она может выбрать `list_indexes`,
а для списка песочниц или MCP — `list_connections`. Портал проверяет аргументы,
читает данные с правами пользователя и передаёт результат модели для ответа.
Если для задачи нужен запуск кода или другой инструмент, агент передаёт её
полному набору инструментов Deep Agents. При временных ошибках агент повторяет
обращения с паузами в пределах четырёх вызовов на шаг.
На уточнение вроде «А какой был предыдущим?» модель получает короткую выдержку
из беседы. Если предмет вопроса остался неясен, она может задать встречный вопрос.
Если модель обрезала ответ или ошиблась в аргументах, портал сообщает ей,
что исправить. Частичный вызов инструмента не исполняется.
При HTTP 422 с указанием на формат инструментов или истории сообщений агент может
продолжить чтение обычным текстовым запросом к той же модели. Он передаёт уже
полученные результаты и учитывает запрет сервера на повторы.
Если сбой случился после выполнения инструмента, агент может попросить ту же модель
кратко переформулировать текущую задачу. Для следующего вызова он возвращает исходный
вопрос, инструменты и результаты поиска или сборки. Черновик формулировки используется
только для этого шага.
Если при подготовке черновика снова возник временный сбой, агент использует последнюю
попытку для ответа на исходный вопрос. Все четыре обращения входят в общий лимит
шага и видны в «Ходе работы».
Если получить ответ так и не удалось, в «Ходе работы» появится номер ошибки.
По нему администратор может найти в журнале портала протокол подключения,
этап сбоя (`stage`), число доступных на этом вызове инструментов (`tools`),
число попыток и HTTP-статус, если поставщик его передал. Для ошибки 422 журнал
различает отказ локального адаптера (`invalid-request`) и ответ API модели
(`upstream-http`). Поле `validation_field` показывает, какую часть запроса
отклонили, когда причина указана однозначно.

Чтобы посмотреть ошибки провайдера на рабочем стенде, из корня репозитория выполните

```bash
./scripts/start-mcp-http.sh logs
```

Последние записи этого типа в журнале стандартного запуска можно вывести отдельно.

```bash
rg 'portal_422|model_422' .cache/kb/runtime/mcp-http.log | tail -n 20
```

Запись `portal_422` означает, что портал отклонил поля формы до вызова модели.
В `model_422` попадают также ошибки, после которых агент восстановился.
По `ref` из «Хода работы» можно найти конкретную попытку, по `trace` — другие
ошибки того же запроса. В `diagnostics` видны структура отправленных сообщений,
параметры вызова и доступные признаки ошибки проверки полей. Для обращения
к владельцу платформы используйте `upstream_request_id`, если API его вернул.

Общий опыт одного подключения хранится в `KB_AGENTS_STATE_DIR/experience.sqlite3`.
В **Настройках модели → Общий опыт этого подключения** видны наблюдения за последние
30 дней. Когда в двух разных завершённых запросах помог один и тот же переход,
агент может начинать следующие запросы с этого способа обращения. Аналогично
он запоминает, когда больший лимит помог завершить ответ по источникам.
При противоречивых результатах для выбора способа действуют настройки подключения.
Отказы поставщика учитываются отдельно. В общей базе хранятся коды исходов,
время и отпечаток подключения. Переписка пользователей остаётся в их чатах.

### Установка

Для обновления существующего стенда на ветке `codex/native-portal-agents`
выполните в рабочем каталоге портала

```bash
git pull --ff-only
./scripts/start-mcp-http.sh restart
```

Для первой установки выполните из корня репозитория с Python 3.12

```bash
./scripts/setup-pip.sh --no-dev --agents
```

В существующем `.env` установите `KB_AGENTS_ENABLED=true`. Перезапустите портал:

```bash
./scripts/start-mcp-http.sh restart
```

Для отключения страницы установите `KB_AGENTS_ENABLED=false` и перезапустите процесс.
После обновления с прежнего Harness открывайте `/agents/`. Сохраните существующий
`.env`, каталог данных и файлы сертификатов. Новый модуль хранит свои данные
в `KB_AGENTS_STATE_DIR` (по умолчанию `var/portal-agents`). История чатов прежнего
Harness остаётся в его каталоге.

### Корпоративный API GigaChat, DeepSeek и GigaCode

Войдите как администратор портала. На странице **Агенты** нажмите название текущей модели вверху и откройте **Настройки модели**.
Для подключения модели через API выбран **Корпоративный API · gpt2giga (по умолчанию)**.
Это относится и к DeepSeek. Введите адрес API GigaChat v1 платформы и имя развёрнутой модели,
если его требует шлюз. Адаптер преобразует сообщения агента, описания инструментов,
их вызовы и результаты между форматами SDK и GigaChat внутри процесса портала.
[Проект gpt2giga](https://github.com/ai-forever/gpt2giga).

Старые API-профили портала и прежнего Harness получают адаптер по умолчанию.
Для прямого вызова шлюза в формате OpenAI Chat Completions администратор может выбрать
**Прямой OpenAI-совместимый API**. Выбранный протокол сохраняется в профиле.

- При обновлении страница автоматически читает профиль модели из
  `configuration.sqlite3` и сохранённый комплект из `tls-credentials/` старого Harness.
  Для встроенного Harness используется `KB_HARNESS_STATE_DIR` (по умолчанию
  `var/harness`), для отдельного запуска — `HARNESS_STATE_DIR` (`var/agent-harness`).
  Если каталог переносили, укажите его фактический путь в окружении сервиса.
- Для подключения к API введите базовый URL или полный адрес Chat Completions.
  Для mTLS выберите файлы CA,
  клиентского сертификата и приватного ключа в формате PEM. Поле токена можно
  оставить пустым. При редактировании своего подключения уже сохранённые файлы
  повторно выбирать не требуется.
- **Проверить запросом** отправляет короткое сообщение с выбранными реквизитами.
- **Проверить исследование** запускает агента с адресом и сертификатами из формы.
  Агент ищет вымышленный журнал, открывает его по найденному идентификатору и называет код
  последней по дате завершённой записи. Журнал содержит две завершённые записи и одну плановую.
  Для каждого запуска создаются новые коды, а строки перемешиваются. Окно показывает текущий
  этап. Если документ прочитан, но агент выбрал более раннюю запись, плановую запись или
  перечислил несколько кодов, вы увидите конкретную ошибку вывода. Проверка этого сценария
  занимает до трёх минут и допускает восемь обращений к модели. Закрытие окна останавливает её.
- **Сохранить** применяет выбор для следующего сообщения во всех чатах.
- Для GigaCode используется системная учётная запись процесса портала. Его можно
  включить на странице и пройти авторизацию по выданной ссылке.

Портал сначала проверяет настройки, сохранённые на новой странице, затем конфигурацию
API в окружении и затем прежний профиль. При первом запуске без настроек выбран GigaCode.
Для развёртывания через окружение доступны следующие параметры.

```dotenv
KB_AGENTS_MODEL_ADAPTER=gpt2giga
KB_AGENTS_MODEL_BASE_URL=https://model.company.example/v1
KB_AGENTS_MODEL_NAME=your-deployed-model
KB_AGENTS_MODEL_CA_FILE=/etc/portal/certs/company-ca.pem
KB_AGENTS_MODEL_CERT_FILE=/etc/portal/certs/client.crt
KB_AGENTS_MODEL_KEY_FILE=/etc/portal/certs/client.key
```

Для прямого вызова OpenAI-совместимого шлюза укажите `KB_AGENTS_MODEL_ADAPTER=openai`.
Настройка окружения задаёт протокол для профилей без сохранённого выбора.
Для шлюза с Bearer-токеном
задайте `KB_AGENTS_MODEL_API_KEY` в окружении сервиса.
Правки `.env` применяются после перезапуска.

### Контейнер, MCP и учётные данные

Откройте **Агенты → Подключения** (`/agents/connections`) под администратором
или введите в чате `/подключения`.
Подключения публикуются для всех пользователей агента. Они доступны со следующего
запроса, включая продолжение уже открытого чата.

| Подключение | Как настроить | Как использует агент |
| --- | --- | --- |
| Docker | Выберите образ на Docker-хосте портала и задайте название среды. Если нужного образа ещё нет, загрузите или соберите его на этом хосте. При сохранении портал проверит образ в пробном контейнере. | При первом обращении к среде агент создаёт отдельный контейнер и выполняет команды через `docker exec` без сетевого порта. Файлы в `/tmp` доступны до конца запроса, затем портал удаляет контейнер. |
| MCP | Выберите зарегистрированный сервер или добавьте имя и Streamable HTTP URL. Для защищённого сервера укажите HTTPS и Bearer-токен. Запросите список инструментов, отметьте нужные операции чтения и сохраните. | Запрашивает актуальные схемы опубликованных инструментов, вызывает их и использует результаты в ответе. Пустой список отключает сервер для агента. |
| Git по SSH | Добавьте источник с понятным ID, полным адресом `ssh://git@host/group/project.git`, незашифрованным приватным ключом сервисной учётной записи и проверенной записью `known_hosts`. Выберите Docker-образ с `tar`. На хосте портала нужны Git, SSH и `ssh-keygen`. | Запрашивает снимок конкретной ветки или тега, получает архив исходников и изучает его внутри контейнера. |
| Зависимости Gradle | Укажите HTTPS-адрес хранилища библиотек из раздела `repositories` проекта. Поддерживается формат Maven, в том числе в Nexus или Artifactory. Для закрытого хранилища введите логин и пароль либо токен в поле пароля. | Портал может скачать отдельный файл по координатам `group:artifact:version` и передать его в контейнер. Данные доступа остаются на сервере. |

Примеры запросов после подключения — «Найди описание PAY-1842 в Jira»,
«Посмотри в ветке main репозитория payments, где обрабатывается тайм-аут».
Связь с Git, хранилищем зависимостей и MCP устанавливает портал.
Если у уже запущенного сервиса есть MCP-сервер, укажите его полный URL в разделе **Серверы MCP**.
Контейнер работает без сети и Docker-сокета. Сохранённые в форме секреты
действуют для указанного подключения.

Ранее заданные в окружении значения действуют до сохранения соответствующего
подключения в интерфейсе.

```dotenv
KB_AGENTS_MCP_READ_TOOLS='{"jira":["get_issue","search_issues"]}'
KB_AGENTS_SANDBOX_IMAGE=company-gradle:jdk21
```

Каталог RAG, индексированный код и граф связей агент получает из действующего портала.

### Сборка и тесты Gradle из чата

1. В разделе **Подключения** выберите **Код Gradle-проекта · Git по SSH** и сохраните адрес проекта с ключом доступа.
2. Выберите Docker-образ с JDK, подходящим проекту. Агент использует `gradlew`
   из репозитория. Подготовьте в образе дистрибутив версии, указанной в
   `gradle/wrapper/gradle-wrapper.properties`. Если в проекте нет Wrapper,
   инструмент запускает установленный в образе `gradle`.
3. В чате укажите репозиторий, ветку и задачу. Например, «В проекте payments
   на ветке main запусти `:api:test` и покажи причину первого падения».
   Агент может получить исходники, запустить Gradle и проверить код завершения и вывод сборки.

Поддерживаются `build.gradle` и `build.gradle.kts`, в том числе в многомодульных
проектах. Сборка выполняется с `--offline`. При подготовке образа прогрейте
кеш запуском нужной задачи на той же версии Gradle. Поместите
`wrapper/dists/` с распакованным дистрибутивом и `caches/modules-2/`
с плагинами и зависимостями в `/opt/portal-gradle-cache/` образа.
Пользователю контейнера (UID 65534) нужен доступ на чтение.
[Подготовка кеша Gradle для контейнеров](https://docs.gradle.org/current/userguide/dependency_caching.html#sec:ephemeral-ci-cache).

Через **Зависимости Gradle · HTTPS** агент может дополнительно загрузить
артефакт, его POM или метаданные Gradle по координатам. В пределах одного запроса
Gradle видит эти файлы в локальном репозитории. Для транзитивных зависимостей
также нужны метаданные и файлы в кеше или локальном репозитории. Сетевые обращения
к хранилищу выполняет портал с реквизитами из формы подключения.

### Чат и подагент

Введите `/` в начале пустого сообщения, чтобы увидеть доступные команды.
Например, `/под` оставит в списке `/подключения`. Выберите строку нажатием
или стрелками ↑/↓ и Enter. Escape закрывает подсказки. Команда `/новый`
начинает чат. Команда `/ресурсы` сразу показывает опубликованную для чата
песочницу и серверы MCP с разрешёнными инструментами. Она читает настройки
напрямую и работает даже при сбое API модели. Администраторам также доступны
`/подключения` и `/модель` для изменения настроек.

Основной агент может делегировать вопрос исследовательскому подагенту штатным
инструментом `task`. Подагент читает доступные ему материалы и возвращает результат
основному агенту. Контрольные точки графа, план и виртуальные рабочие файлы
сохраняются через LangGraph в SQLite. Чат привязан к учётной записи и идентификатору
диалога. Новый диалог начинает с отдельного состояния. Кнопка удаления очищает
переписку и контрольные точки диалога. Рабочие файлы в контейнере живут до конца
текущего запроса. Переписка одного сотрудника не пополняет общую память АС автоматически.

### Почему выбран Deep Agents

| Фреймворк | Применение в этом портале |
| --- | --- |
| **Deep Agents SDK** | Вошёл в реализацию. Есть готовый цикл выбора инструментов, делегирование и управление контекстом. Существующий GigaCode и корпоративный API можно подать SDK через интерфейс чат-модели LangChain. [Документация Deep Agents](https://docs.langchain.com/oss/python/deepagents/overview) |
| **Claude Agent SDK** | Подходит для развёртывания с Claude. Потребуется поддерживаемый провайдер Claude. Зарегистрированный RAG можно подключить по MCP. [Обзор Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) · [Модели и среды исполнения](https://docs.langchain.com/oss/python/deepagents/comparison) |
| **Pydantic AI** | Подходит для набора специализированных агентов с типизированными входами и результатами. Есть совместимые API и несколько способов делегирования. Для нашего CLI понадобился бы отдельный адаптер модели этого фреймворка. [Модели](https://ai.pydantic.dev/models/openai/) · [Мультиагентные приложения](https://ai.pydantic.dev/multi-agent-applications/) |
