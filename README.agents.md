# Агенты портала

Страница **Агенты** доступна по адресу `/agents/`. Это чат с агентом Deep Agents SDK.
Модель сама выбирает следующий шаг. На обычный вопрос она может ответить сразу.
Для отдельного приветствия вроде «Привет, как дела?» SDK обращается к модели
с пустым списком инструментов. У приветствия, за которым следует задача,
доступ к инструментам сохраняется.
Для вопроса о релизе она может запросить список индексов, выбрать один по описанию,
выполнить поиск, открыть найденный документ и сопоставить дату с записью из MCP.
Выбор зависит от вопроса, доступных инструментов и фактических результатов.
В чате отображаются обращения к модели и вызовы инструментов.

### Установка

Выполните из корня репозитория с Python 3.12:

```bash
./scripts/setup-pip.sh --no-dev --agents
```

В существующем `.env` установите `KB_AGENTS_ENABLED=true`. Перезапустите портал:

```bash
./scripts/start-mcp-http.sh restart
```

Для отключения страницы установите `KB_AGENTS_ENABLED=false` и перезапустите процесс.
После обновления с прежнего Harness открывайте `/agents/`. Сохраните существующий
`.env`, каталог данных и файлы сертификатов. Новый модуль хранит свои данные
в `KB_AGENTS_STATE_DIR` (по умолчанию `var/portal-agents`). История чатов прежнего
Harness остаётся в его каталоге.

### DeepSeek и GigaCode

Войдите как администратор портала. На странице **Агенты** нажмите название текущей модели вверху и откройте **Настройки модели**.
В списке доступны **GigaCode** и **Корпоративный API · DeepSeek и другие**.

- При обновлении страница автоматически читает профиль модели из
  `configuration.sqlite3` и сохранённый комплект из `tls-credentials/` старого Harness.
  Для встроенного Harness используется `KB_HARNESS_STATE_DIR` (по умолчанию
  `var/harness`), для отдельного запуска — `HARNESS_STATE_DIR` (`var/agent-harness`).
  Если каталог переносили, укажите его фактический путь в окружении сервиса.
- Для нового подключения к API введите адрес Chat Completions или базовый URL.
  Имя модели нужно, если его требует шлюз. Для mTLS выберите файлы CA,
  клиентского сертификата и приватного ключа в формате PEM. Поле токена можно
  оставить пустым. При редактировании своего подключения уже сохранённые файлы
  повторно выбирать не требуется.
- **Проверить запросом** отправляет короткое сообщение с выбранными реквизитами.
  **Сохранить** применяет выбор для следующего сообщения во всех чатах.
- Для GigaCode используется системная учётная запись процесса портала. Его можно
  включить на странице и пройти авторизацию по выданной ссылке.

Портал сначала проверяет настройки, сохранённые на новой странице, затем конфигурацию
API в окружении и затем прежний профиль. При первом запуске без настроек выбран GigaCode.
Для развёртывания через окружение доступны следующие параметры.

```dotenv
KB_AGENTS_MODEL_BASE_URL=https://model.company.example/v1
KB_AGENTS_MODEL_NAME=your-deployed-model
KB_AGENTS_MODEL_CA_FILE=/etc/portal/certs/company-ca.pem
KB_AGENTS_MODEL_CERT_FILE=/etc/portal/certs/client.crt
KB_AGENTS_MODEL_KEY_FILE=/etc/portal/certs/client.key
```

Для шлюза с токеном задайте `KB_AGENTS_MODEL_API_KEY` в окружении сервиса.
Правки `.env` применяются после перезапуска.

### Контейнер, MCP и учётные данные

Откройте **Агенты → Подключения** (`/agents/connections`) под администратором
или введите в чате `/подключения`.
Подключения публикуются для всех пользователей агента. Они доступны со следующего
запроса, включая продолжение уже открытого чата.

| Подключение | Как настроить | Как использует агент |
| --- | --- | --- |
| Docker | Выберите образ из локального списка, задайте название среды и сохраните. Портал запустит пробный контейнер. Если образа ещё нет, сначала загрузите или соберите его на том Docker-хосте, с которым работает портал. | По необходимости запускает отдельный контейнер на один запрос. Внутри запроса между шагами доступны одни и те же файлы в `/tmp`. После завершения контейнер удаляется. |
| MCP | Выберите зарегистрированный сервер или добавьте имя и Streamable HTTP URL. Для защищённого сервера укажите HTTPS и Bearer-токен. Запросите список инструментов, отметьте нужные операции чтения и сохраните. | Запрашивает актуальные схемы опубликованных инструментов, вызывает их и использует результаты в ответе. Пустой список отключает сервер для агента. |
| Git по SSH | Добавьте источник с понятным ID, полным адресом `ssh://git@host/group/project.git`, незашифрованным приватным ключом сервисной учётной записи и проверенной записью `known_hosts`. Выберите Docker-образ с `tar`. На хосте портала нужны Git, SSH и `ssh-keygen`. | Запрашивает снимок конкретной ветки или тега, получает архив исходников и изучает его внутри контейнера. |
| Зависимости Gradle из Maven | Добавьте HTTPS-адрес репозитория Maven, логин и пароль либо токен в поле пароля. Для публичного репозитория оставьте оба поля пустыми. | Скачивает конкретный артефакт по координатам `group:artifact:version` для работы внутри контейнера. Полная онлайн-сборка Gradle с автоматической загрузкой зависимостей в этом режиме недоступна. |

Примеры запросов после подключения — «Найди описание PAY-1842 в Jira»,
«Посмотри в ветке main репозитория payments, где обрабатывается тайм-аут».
Связь с Git, Maven и MCP устанавливает портал. Секреты остаются на сервере.
Контейнер работает без сети и Docker-сокета. Сохранённые в форме секреты
действуют для указанного подключения.

Ранее заданные в окружении значения действуют до сохранения соответствующего
подключения в интерфейсе.

```dotenv
KB_AGENTS_MCP_READ_TOOLS='{"jira":["get_issue","search_issues"]}'
KB_AGENTS_SANDBOX_IMAGE=python:3.12-alpine
```

Каталог RAG, индексированный код и граф связей агент получает из действующего портала.

### Чат и подагент

Основной агент может делегировать вопрос исследовательскому подагенту штатным
инструментом `task`. Подагент читает доступные ему материалы и возвращает результат
основному агенту. Контрольные точки графа, план и виртуальные рабочие файлы
сохраняются через LangGraph в SQLite. Чат привязан к учётной записи и идентификатору
диалога. Новый диалог начинает с отдельного состояния. Кнопка удаления очищает
переписку и контрольные точки диалога. Рабочие файлы в контейнере живут до конца
текущего запроса. Переписка одного сотрудника не пополняет общую память АС автоматически.

### Почему выбран Deep Agents

| Фреймворк | Применение в этом портале |
| --- | --- |
| **Deep Agents SDK** | Вошёл в реализацию. Есть готовый цикл выбора инструментов, делегирование и управление контекстом. Существующий GigaCode и корпоративный API можно подать SDK через интерфейс чат-модели LangChain. [Документация Deep Agents](https://docs.langchain.com/oss/python/deepagents/overview) |
| **Claude Agent SDK** | Подходит для развёртывания с Claude. Потребуется поддерживаемый провайдер Claude. Зарегистрированный RAG можно подключить по MCP. [Обзор Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) · [Модели и среды исполнения](https://docs.langchain.com/oss/python/deepagents/comparison) |
| **Pydantic AI** | Подходит для набора специализированных агентов с типизированными входами и результатами. Есть совместимые API и несколько способов делегирования. Для нашего CLI понадобился бы отдельный адаптер модели этого фреймворка. [Модели](https://ai.pydantic.dev/models/openai/) · [Мультиагентные приложения](https://ai.pydantic.dev/multi-agent-applications/) |
