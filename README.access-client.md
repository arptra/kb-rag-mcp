# Подключение клиента через личный сертификат

Этот способ предназначен для сервера с включённым модулем управления доступами.
Администратор сервера должен настроить доверенный центр сертификации клиентов.
Обычный серверный TLS-сертификат не заменяет личный клиентский сертификат.

При первом подключении клиент подтверждает владение личным ключом через mTLS,
а сервер выдаёт персональный Bearer-токен. При последующих запросах MCP сервер
проверяет токен и состояние пользователя в своей базе. Отозванный доступ нельзя
восстановить простым удалением токена: нужен администратор.

Для проверки всей цепочки на своём компьютере запустите
`./scripts/start-mcp-http.sh local --setup`: профиль сам подготовит Python 3.12,
тестовые сертификаты, пароли и изолированный HTTPS-сервер. Для сервера на Debian и
браузера на другом компьютере добавьте `--host 0.0.0.0 --server-name <IP-или-DNS>`.
Однократный импорт CA и личного P12, включая клиентский ZIP, описан в
[инструкции локального запуска](README.access.md#проверка-на-localhost-одной-командой).

## Получить MCP конфиг через браузер

Python и клиентский помощник для этого варианта не нужны. Достаточно браузера с личным
сертификатом и MCP-клиента, поддерживающего `httpUrl` и `headers.Authorization`.

1. Установите личный сертификат вместе с закрытым ключом в хранилище браузера или ОС.
   Один публичный `.crt` без соответствующего ключа не подтверждает вашу личность.
2. Откройте `https://<сервер>:<порт>/connect`. Если браузер предложит выбрать сертификат,
   выберите личный сертификат, выданный вашей организацией.
3. Нажмите «Получить MCP-конфиг». Сервер проверит сертификат и статус доступа, затем
   вернёт готовый JSON с адресом MCP и вашим персональным Bearer-токеном.
4. Скопируйте JSON или скачайте `corporate-kb.mcp.json`. В существующих настройках MCP
   добавьте или замените **только** запись `mcpServers.corporate-kb`, сохранив другие
   серверы и параметры. Если одноимённая запись уже указывает на другой сервис,
   сначала выберите для нового подключения другое имя.
5. Переподключите MCP-сервер в клиенте. Дальнейшие запросы идут напрямую по HTTPS с токеном.

Для GigaCode конфиг находится в `~/.gigacode/settings.json` на Linux/macOS или
`%USERPROFILE%\.gigacode\settings.json` на Windows. Поддержка конкретной схемы настроек
зависит от версии MCP-клиента; если он не принимает `httpUrl` + заголовки, используйте
поддерживаемую им схему или stdio-помощник ниже.

Страница не загружает закрытый ключ на сервер и не читает его через JavaScript:
подтверждение владения ключом делает браузер при TLS-соединении. Если сертификат не
предъявлен, страница объяснит, как его установить; обычной сессии дашборда недостаточно.
Для выдачи не нужен вход администратора. Сертификат самого сервера должен быть доверен
и браузеру, и MCP-клиенту.

JSON содержит секрет. Не коммитьте его, не отправляйте в чат или тикет и не оставляйте
в общедоступной папке загрузок. Скачивание браузером не выставляет автоматически права
`0600`; защитите файл средствами ОС. Копирование в буфер обмена выполняется только по
нажатию кнопки и может оставлять запись в истории буфера обмена.

В этом варианте нет автоматического редактирования настроек на компьютере. После
истечения токена снова откройте `/connect`, получите конфиг и замените запись в клиенте.
Повторная выдача в том же браузере переиспользует действующий экспортный токен через
отдельную защищённую cookie. Выход из дашборда **не отзывает** скачанный MCP-токен.
Отзыв токена или всего пользователя доступен администратору в `/access-admin`.

## Что нужно для клиентского помощника

- Python 3.12 и установленный пакет проекта с командой `kb-access`.
- Личный сертификат и соответствующий приватный ключ в PEM-формате.
- HTTPS-адрес сервера, например `https://rag.company.example:8000`.
- Путь к JSON-настройкам вашего MCP-клиента.
- При необходимости — PEM-файл доверенного CA сервера.

Команда `python -m corporate_kb.access.client` равнозначна `kb-access`, если
используется Python из того же окружения, в котором установлен пакет.

Ключ остаётся на вашем компьютере: команда использует его для TLS-подписи,
а не отправляет на сервер в JSON, заголовке или файле. Закрытый ключ, токен
и готовый файл настроек нельзя коммитить в Git или передавать другим людям.

Команда не запрашивает пароль зашифрованного PEM-ключа. Для автоматического
stdio-подключения нужен доступный процессу локальный ключ без интерактивного
пароля; защитите его правами файловой системы. Смарт-карты, аппаратные токены,
PKCS#11 и системные хранилища личных ключей этим помощником не поддерживаются.

## Автоматическая проверка через клиентский помощник

Выполните на клиентском компьютере, заменив адреса и пути:

```bash
kb-access connect \
  --server-url 'https://rag.company.example:8000' \
  --cert '/path/to/personal-client.crt' \
  --key '/path/to/personal-client.key' \
  --ca '/path/to/trusted-server-ca.pem' \
  --config '/path/to/mcp-settings.json' \
  --name corporate-kb \
  --transport stdio
```

Если серверный сертификат уже доверен вашей ОС, уберите `--ca`. Отключить проверку
сертификата или hostname через эту команду нельзя. HTTPS-адрес должен быть базовым:
без `/mcp`, логина, пароля, query-параметров и fragment.

Команда получает токен и изменяет только выбранный элемент `mcpServers` в явно
указанном локальном JSON. Остальные настройки и MCP-серверы сохраняются. Путь
к настройкам не угадывается автоматически. Каталог назначения должен существовать.

В записи появятся `command`, `args` и `env.KB_ACCESS_TOKEN`. Команда ссылается на
конкретный Python текущего окружения; не удаляйте это окружение после настройки.
Если перенесли окружение или сертификат, выполните `connect` с новыми путями.

Затем перезапустите MCP-клиент или отключите и подключите этот сервер заново.
При каждом новом запуске локального stdio-процесса помощник:

1. Читает актуальный токен из выбранного файла настроек.
2. Подключается к `/auth/token` по mTLS с личным сертификатом.
3. Переиспользует действующий токен или получает новый, если старый истёк/неизвестен
   и доступ владельца сертификата разрешён.
4. При замене токена атомарно обновляет только свою запись в настройках.
5. Передаёт MCP-запросы по HTTPS на сервер с Bearer-токеном.

Сам RAG-индекс, документы и исполнение тулов остаются на общем сервере: локальный
процесс — только транспортный посредник. Обновления списка тулов приходят с сервера.
Stdout процесса используется только для протокола MCP, без печати токенов.

Это обновление **при запуске нового процесса**, а не фоновая ротация внутри бесконечно
долгой сессии. Если срок токена истёк в работающей сессии, переподключите MCP-сервер.
При каждом новом удалённом запросе сервер всё равно проверяет действительность
токена; отзыв доступа не ждёт следующего запуска локального процесса.

## Прямой HTTPS без локального посредника

Если клиент поддерживает `httpUrl` и заголовки MCP, можно использовать:

```bash
kb-access connect \
  --server-url 'https://rag.company.example:8000' \
  --cert '/path/to/personal-client.crt' \
  --key '/path/to/personal-client.key' \
  --ca '/path/to/trusted-server-ca.pem' \
  --config '/path/to/mcp-settings.json' \
  --name corporate-kb \
  --transport http
```

`http` — режим по умолчанию. Сохранённая запись имеет такой формат:

```json
{
  "mcpServers": {
    "corporate-kb": {
      "httpUrl": "https://rag.company.example:8000/mcp",
      "headers": {
        "Authorization": "Bearer <персональный токен>"
      }
    }
  }
}
```

Это ожидаемая JSON-схема интеграции, а не гарантия поддержки каждой версии GigaCode
или другого MCP-клиента. Проверьте поддержку `httpUrl` + `headers` в вашей версии;
при отсутствии этой поддержки используйте stdio-вариант, если клиент поддерживает
`command`/`args`/`env`. Сервер не может самостоятельно переписать файлы на другом
компьютере и не имеет встроенного механизма изменения клиентских настроек MCP.

В прямом HTTP-режиме повторите ту же команду `connect`, когда токен истечёт, затем
переподключите клиент. Сертификат используется при выдаче/продлении токена,
а обычные MCP-запросы используют Bearer без личного сертификата.
Параметр `--ca` настраивает доверие помощника, но не системное доверие GigaCode:
прямой клиент должен отдельно доверять CA серверного сертификата.

## Замена записи и защита настроек

Если запись с таким именем указывает на другой сервер или использует другой
транспорт, команда остановится. Для осознанной замены добавьте `--replace` или
выберите другое `--name`. При смене origin старый Bearer-токен новому серверу
не отправляется. `--replace` удаляет конкурирующие поля транспорта только в
выбранной записи и не удаляет другие MCP-серверы.

Перед записью проверяются синтаксис JSON, типы полей и отсутствие дублирующихся
JSON-ключей. Символьная ссылка или не обычный файл в качестве назначения отвергаются.
Помощник проверяет, не изменился ли файл за время сетевого запроса; если изменился,
он останавливается, не перезаписывая чужие изменения. Закройте редактор настроек
на время подключения и повторите команду. Несотрудничающие процессы могут изменить
файл уже после проверки; это не межпроцессная транзакционная блокировка.

Файл заменяется атомарно, на POSIX устанавливаются права `0600` (только владелец).
На Windows проверяйте ACL файла и родительского каталога отдельно: POSIX-биты
не обеспечивают эквивалентную ACL-защиту. Не храните настройки в общедоступном
каталоге, общем сетевом ресурсе или репозитории. Токен в локальном конфиге — секрет.

## Ошибки

- `Access denied or revoked` / HTTP 403: обратитесь к администратору; повторная
  регистрация тем же сертификатом не обходит блокировку.
- Ошибка TLS: проверьте срок и назначение личного сертификата, соответствие ключа,
  CA сервера и совпадение hostname с серверным сертификатом.
- Ошибка redirect: укажите окончательный HTTPS-адрес сервера. Автоматический
  переход на другой адрес при обмене сертификатом/токеном запрещён.
- `Config changed`: другой процесс изменил настройки. Повторите после завершения
  его работы; файл с чужими изменениями не перезаписывается.
- Ошибка сети: конфиг не обновляется. Автоматическое использование прокси из
  `HTTP_PROXY`/`HTTPS_PROXY` отключено; необходим прямой доступ к HTTPS-серверу.

Не отправляйте администратору приватный ключ, токен или полный файл настроек.
Достаточно безопасного текста ошибки, времени попытки и имени сервера.
