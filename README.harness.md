# Отдельный модуль «Харнес»

Харнес вынесен в `src/agent_harness`: собственная страница, HTTP API, настройки,
очереди, политика усилия и SQLite-история. Пакет не импортирует код портала, RAG,
GigaCode или LangChain. Страница — самостоятельные HTML/CSS/JS без сборки dashboard.

Портал подключает его через один адаптер `corporate_kb.harness_integration`.
Адаптер передаёт авторизацию, доступ к текущим индексам и при наличии настройки —
GigaCode. Направление зависимости: **портал → адаптер → интерфейсы харнеса**.

Эта экспериментальная страница и её модельный адаптер настраиваются отдельно от
штатного агента A2A. Для кнопки «Включить агента» во вкладке A2A не нужны ни
`KB_HARNESS_ENABLED`, ни профиль `KB_HARNESS_MODEL_PROFILE_PATH`: там используется
уже рабочий запуск GigaCode для анализа. Инструкция: [агент A2A](README.agent-activation.md).

## Включить или выключить

По умолчанию модуль выключен. В `.env`:

```dotenv
KB_HARNESS_ENABLED=true
KB_HARNESS_STATE_DIR=./var/harness
```

После перезапуска backend отдельная страница доступна на `/harness/`, а в навигации
собранного dashboard появляется ссылка «Харнес». Саму страницу харнеса собирать не нужно.
Она использует личную сессию портала. При старой схеме авторизации можно ввести Bearer
token или пароль администратора в форме страницы; данные остаются в текущей вкладке.

`KB_HARNESS_ENABLED=false` и перезапуск отключают страницу `/harness/`, её API,
собственные workers и создание её хранилища. Это не просто скрытие кнопки.
Агент A2A независимо использует общий runtime из пакета `agent_harness`;
эта настройка не отключает его и не запрещает импорт общего пакета.
При штатной остановке активные работы отменяются; история на диске сохраняется.
Следующее включение снова использует этот каталог. При аварии незавершённые работы
помечаются `interrupted`, автоматическое продолжение не заявляется.

Ни один запрос харнеса не выполняет изменение источников. Текущий адаптер читает
выбранные RAG-индексы и документы. Документация и сведения из репозиториев доступны
в той мере, в какой уже попали в эти индексы. Прямое исследование checkout, Jira,
Drop и БД, общий слой проверенной памяти и MCP-вход к харнесу остаются следующими
интеграциями. Их добавляют через интерфейсы модуля, а не в основной dashboard.

## Режимы и усилие

- **Быстро:** ограниченный параллельный сбор источников и один итоговый вызов модели.
  Найденные материалы появляются до готовности объяснения. По умолчанию бюджет
  выполнения — 20 секунд после выхода из очереди; при его исчерпании начинается
  отмена провайдера, очистка которого может потребовать дополнительного времени.
- **Исследовать:** сбор, дополнительные поиски и чтение документов по решениям модели,
  затем итог. Пользователь видит действующий этап и может отменить работу.
- **Усилие:** низкое, обычное, высокое. Меняет лимиты обращений к источникам, контекста
  и шагов исследования, а также число и размер фрагментов даже при одном индексе.
  Это исполняемая политика сервиса, не неподдерживаемый
  `reasoning_effort` GigaCode. Высокое усилие не гарантирует правильность ответа.
- **Исследовать глубже:** новый связанный запуск с вопросом предыдущего разбора.
  Источники читаются заново; предыдущий ответ не считается подтверждённым фактом.

Очереди быстрых запросов и исследований разделены. Общие лимиты внешнего провайдера
при этом сохраняются: мгновенный свежий ответ через CLI не обещается. Токенный streaming
не реализован; страница опрашивает статус и показывает реальные готовые данные.

Без модели поиск работает: результат помечается частичным, показываются найденные
материалы и причина отсутствия синтеза. Вместо анализа не выводится имитация ответа.

## Подключить GigaCode к экспериментальной странице /harness/

Профиль ниже нужен только этому отдельному модельному адаптеру. Штатный агент A2A
не читает этот файл и работает без него, в том числе если ранее заданный путь неверен.

```sh
uv sync --extra agents --inexact
```

Укажите `KB_GIGACODE_COMMAND` на проверенный launcher и
`KB_HARNESS_MODEL_PROFILE_PATH` на JSON с полями `name`, `cli_version`, `arguments`
(массив строк), `isolation_notes`. Требования к отключению нативных инструментов,
MCP и постороннего контекста описаны в [плане](README.agent-service.md).
Профиль конфигурирует администратор; интерфейс его не принимает и не показывает.
Версия сверяется при каждом вызове. Настоящий GigaCode в среде разработки не установлен;
его совместимость и задержки ещё нужно проверить на стенде.

## Хранение и пользователи

История живёт только в `KB_HARNESS_STATE_DIR/runs.sqlite3`. Запуски принадлежат
серверному `owner_id`; браузер не задаёт этот идентификатор. Чтение и отмена чужого
запуска возвращают 404. Отозванная личная сессия не даёт читать историю; права
повторно проверяются перед чтением источника и после него.

В текущем портале право читать RAG является общим для авторизованных пользователей;
новая система индивидуальных ACL документов здесь не создаётся. При исчезновении
доступа к индексу сохранённый ответ и его evidence скрываются. Сохранение истории
не является общей памятью и не обучает модель.

Для личной истории сотрудников используйте `KB_ACCESS_ENABLED=true` с личными
учётными записями портала. Общий legacy token/пароль означает общую учётную запись,
а не 100 независимых сотрудников. В режиме без пароля доступ разрешён только локальному
клиенту как одному рабочему пространству разработки.

Дополнительные параметры из `agent_harness.config.HarnessSettings` имеют префикс
`HARNESS_`: workers каждой очереди, размер очередей, таймауты, лимит контекста и evidence,
срок хранения и число записей. По умолчанию хранятся до 100 завершённых запусков на
пользователя, до 10 000 всего, до 30 дней. SQLite и очереди рассчитаны на один процесс;
для нескольких workers/реплик нужны внешняя очередь и хранилище.

## Запустить отдельно

В этом репозитории можно запустить отдельный процесс, читающий настроенные индексы:

```sh
export HARNESS_API_TOKEN='<отдельный секрет не короче 32 символов>'
export HARNESS_STATE_DIR='./var/harness-standalone'
export HARNESS_PROVIDER_FACTORY='corporate_kb.harness_integration:standalone_providers'
PYTHONPATH=src .venv/bin/python -m agent_harness
```

Страница: `http://127.0.0.1:8020/`. Standalone-токен представляет одну общую учётную
запись. Для нескольких личных пользователей подключается собственный `authenticate`
к `create_app`. Не запускайте standalone и встроенный модуль с одним каталогом истории.

Для физического выделения в отдельный проект:

```sh
.venv/bin/python scripts/export-harness.py /tmp/independent-agent-harness
```

Команда создаёт новый каталог с `pyproject.toml`, документацией и только пакетом
`agent_harness`; существующий каталог не перезаписывается. Корпоративные адаптеры
не копируются. В отдельном проекте реализуются `SourcePort` и `ModelPort`, а доверенная
фабрика подключается через `HARNESS_PROVIDER_FACTORY`. Без неё страница запускается
с явным сообщением об отсутствии источников и модели.

## Проверка

```sh
PYTHONPATH=src .venv/bin/pytest -q tests/test_harness_runtime.py tests/test_harness_http.py tests/test_harness_integration.py
```

Проверки покрывают флаг выключения, отдельные маршруты и хранилище, реальный поиск
по тестовому RAG, границы пользователей, усилие и бюджеты, отмену, restart и HTTP.
Модель в тестах подменяется; проверки не подтверждают live-совместимость GigaCode.
