# A2A: отдельный доступ для агентов

Вкладка **A2A** показывает зарегистрированных агентов, журнал запросов и отдельные
счётчики A2A. В **Получение доступа → A2A** администратор создаёт агенту токен,
выбирает доступные индексы и срок действия (1–365 дней). Подключение агента требует
только токен; клиентский сертификат не нужен. В режиме реестра доступов выдача
токенов защищена существующей администраторской сессией и CSRF. В старом режиме
используется административный пароль (либо настроенный общий токен, если пароля нет).

Токен показывается при выпуске/ротации один раз; сервер сохраняет SHA-256 отпечаток.
Ротация сразу отменяет прежний токен, отзыв закрывает доступ агенту. A2A-токен не
подходит для MCP или административных API. Название агента в журнале определяется
по токену, а не из тела запроса. Статистика MCP не увеличивается от запросов A2A.
На общедоступном сервере следует использовать существующий HTTPS listener.

Реализован [A2A 1.0 JSON-RPC](https://a2a-protocol.org/v1.0.1/specification/):
Agent Card — `/.well-known/agent-card.json`, endpoint по умолчанию — `/a2a`.
Поддержаны `SendMessage`, `GetTask`, `ListTasks`, `CancelTask`, синхронная выдача
и `configuration.returnImmediately=true` с последующим опросом задачи. Streaming
и push notifications не объявляются и возвращают соответствующую ошибку протокола.
Это агент поиска документации: результатом являются фрагменты, ссылки и версии,
а не сгенерированный внешней моделью ответ.

Выдаваемый конфиг теперь содержит `protocol`, `protocolVersion`, `supportedMethods`,
инструкцию `instructions` и готовое тело `requestExample`. Перед каждым новым вопросом
нужно заменить `messageId`; повтор с тем же ID допустим только для того же запроса.
Это описание подключения A2A, а не конфигурация MCP-сервера.
`GET /a2a` возвращает ту же инструкцию и пример без секретного токена: агент может
сначала прочитать её, затем выполнить `POST` со своим токеном. Для примера 0.3
используется `GET /a2a?A2A-Version=0.3`. Чтение инструкции не увеличивает счётчик.

### Совместимость и Method not found

Для клиентов A2A 0.3 поддержаны `message/send`, `tasks/get`, `tasks/cancel` на том же
endpoint и с тем же агентским токеном. Укажите `A2A-Version: 0.3` (принимается и
`0.3.0`). Старые методы без заголовка версии также используют формат 0.3. Для 1.0
заголовок `A2A-Version: 1.0` обязателен. Явная версия определяет формат: смешивание
методов 0.3 с заголовком 1.0 возвращает подсказку, а не незаметную смену протокола.

В формате 0.3 сообщение содержит `kind: "message"`, `role: "user"`, а части —
`kind: "text"` или `kind: "data"`. `configuration.blocking: false` включает фоновую
задачу. Ответ `message/send` содержит задачу прямо в `result`, со статусом вроде
`completed`; в 1.0 задача находится в `result.task`, статус — `TASK_STATE_COMPLETED`.
Прикладные данные внутри артефактов не преобразуются. Streaming, push notifications
и расширенная карточка по-прежнему не поддерживаются.

Карточка по умолчанию остаётся в формате 1.0. Для 0.3 используйте
`/.well-known/agent-card.json?A2A-Version=0.3`, заголовок `A2A-Version: 0.3` при
чтении карточки или совместимый адрес `/.well-known/agent.json`.

`initialize`, `tools/list`, `tools/call` — методы MCP. Если они попали на `/a2a`,
нужно настроить клиент A2A, поставить адаптер MCP → A2A или использовать отдельное
подключение MCP с его учётными данными. Агентский A2A-токен не открывает `/mcp`.
Сервер возвращает понятную причину, поддержанные методы и пример вызова в
`error.data`; журнал сохраняет фактическое имя метода даже при ошибке версии.

MCP предоставляет инструменты для прямого вызова. A2A принимает сообщения, создаёт
задачи, позволяет читать их состояние и отменять выполнение. В этом проекте оба
интерфейса обращаются к одному поиску по индексам; A2A не добавляет отдельную модель,
планирование или автономное исследование. Права агентов, задачи и счётчики A2A
хранятся отдельно от MCP.

### GigaAgent

В проверенном публичном [ai-forever/giga_agent, commit e02715f](https://github.com/ai-forever/giga_agent/tree/e02715ff2d1a29192f167d385647064a2ff5d2e5)
внешние серверы подключаются через MCP. Например,
[backend MCP client](https://github.com/ai-forever/giga_agent/blob/e02715ff2d1a29192f167d385647064a2ff5d2e5/backend/giga_agent/modules/mcp/client.py)
создаёт `mcp.ClientSession` и вызывает `initialize()`; это не вызов A2A.
Поэтому в настройку MCP нельзя подставлять `/a2a` с агентским токеном: используйте
адрес MCP и выданный для MCP конфиг. Для подключения через A2A-токен из такого
MCP-клиента понадобится отдельный адаптер MCP → A2A; он здесь не реализован.

Если адрес и токен переданы прямо в чат GigaAgent, а не в настройку MCP, агенту
следует сначала прочитать `GET /a2a`, затем отправить приведённый там пример POST.
Для этого в его среде должно быть разрешено выполнение HTTP-запросов к серверу.
Поддержка A2A 0.3 не превращает штатный MCP-коннектор GigaAgent в клиент A2A.
Корпоративная сборка или форк могут отличаться от проверенной публичной версии.

Пример запроса (подставить выданный токен только в заголовок):

```http
POST /a2a
Authorization: Bearer <agent-token>
A2A-Version: 1.0
Content-Type: application/json
```

```json
{
  "jsonrpc": "2.0",
  "id": "request-1",
  "method": "SendMessage",
  "params": {
    "message": {
      "messageId": "unique-message-id",
      "role": "ROLE_USER",
      "parts": [{"data": {
        "action": "search",
        "index_id": "default",
        "query": "Как работает авторизация?",
        "version_scope": "latest",
        "top_k": 3
      }}]
    }
  }
}
```

Обычная часть `{"text":"вопрос"}` ищет по всем разрешённым агенту индексам.
`messageId` уникален для логического запроса: повтор возвращает ту же задачу;
изменение запроса при прежнем ID отклоняется. Задачи принадлежат конкретному
агенту: чужой токен не позволяет читать или отменять их. После перезапуска
незавершённые задачи получают статус FAILED с указанием причины.

Действия в `parts[].data`:

| action | Параметры | Результат |
|---|---|---|
| `search` | `query`, необязательные `index_id`, `top_k`, `page_id` | Только текущие страницы |
| `document` | `index_id`, `document_id` | Найденный текущий документ |
| `document` | `index_id`, `page_id` | Последняя загруженная страница |
| `chunk` | `index_id`, `chunk_id` | Цитируемый фрагмент текущего документа |
| `versions` | `index_id`, `page_id`, `limit`, `offset` | Совместимость со старыми клиентами: максимум одна текущая страница без полного текста |

Поиск и чтение всегда используют последние загруженные страницы. Старые аргументы
`version_scope`, `as_of` и `source_version` принимаются для совместимости, но не
выбирают прошлую редакцию: ответ содержит `version_scope: "latest"`, `as_of: null`.
Прямые ссылки на устаревшие `document_id` и `chunk_id` недоступны; агенту следует
повторить поиск или прочитать страницу по `page_id`.
Поля `source_version`, `source_updated_at`, `revision_updated_at` и `fetched_at`
описывают текущий документ; `source_updated_at` — дата изменения страницы,
`revision_updated_at` учитывает изменение вложений. Текст документа и результат
распознавания изображения являются данными источника, не инструкциями агенту.
Agent Card описывает поиск и чтение только текущих страниц.

Настройки: `KB_A2A_ENABLED=true`, `KB_A2A_PATH=/a2a`,
`KB_A2A_STATE_DIR=var/a2a`, `KB_A2A_MAX_REQUEST_BYTES=65536`.
Каталог состояния содержит SQLite с агентами, задачами и журналом. Его необходимо
сохранять при перезапусках и включать в резервное копирование. Запросы в журнале
ограничены по длине, токены не записываются. Счётчики учитывают обработанные
аутентифицированные HTTP-вызовы; опросы GetTask считаются отдельными вызовами.

На главной странице рядом с «Вызовы» показана отдельная карточка **«Вызовы A2A»**:
общее число обработанных обращений и число за последнюю минуту. Она использует ту
же сохранённую статистику, что вкладка A2A, включая успешные запросы и ошибки.
Запросы без действительного токена, чтение Agent Card и обновление самой панели
в этот счётчик не входят. Данные доступны в `a2a_usage` ответа
`GET /admin/api/overview`; при отключённом A2A поле `enabled` равно `false`.
